# laser_sender

Пульт для лазерного станка (GRBL) прямо с Android‑планшета — **без ноутбука и без сервера**.
Планшет подключается к станку по USB‑OTG, а браузер общается с платой через **WebUSB** и
**написанный вручную драйвер CH340/CH341** (Web Serial не видит эти микросхемы, поэтому
используется низкоуровневый доступ к USB).

## Связь со станком (этап A)

`index.html` — самодостаточная страница: терминал + визуализатор G‑кода + пульт.
В части связи она:

1. показывает окружение (`isSecureContext`, наличие `navigator.usb` / `navigator.serial`);
2. подключается к CH340/CH341 через WebUSB (`requestDevice` → `open` → `claimInterface` → init → baud);
3. настраивает скорость (по умолчанию **115200**, 8N1) и линии DTR/RTS;
4. умеет отправлять команды GRBL: `?`, `$I`, `$$`, `$X`, `$H`, soft reset (Ctrl‑X), импульс DTR;
5. показывает всё, что отвечает станок, в логе.

### Станок (проверено на ПК)

Станок подключён к ноутбуку, LaserGRBL его видит. Фактические данные устройства:

| Параметр | Значение |
|---|---|
| Имя устройства | `USB-SERIAL CH340` |
| VID:PID | `0x1A86 : 0x7523` |
| Порт на ПК | `COM9` |
| Драйвер Windows | `wch.cn 3.9.2024.9` (INF `oem41.inf`, служба `CH341SER_A64`) |
| ID экземпляра | `USB\VID_1A86&PID_7523\6&158D80E5&1&3` |

**Вывод:** чип — обычный **CH340** (`1A86:7523`), ровно тот, под который написан драйвер
в `index.html` (и первый фильтр в списке теперь точно на этот PID). Значит, если на планшете
пикер **пуст** — дело **не в фильтре и не в драйвере**, а в физическом подключении (OTG).

### Как открыть на планшете

1. Скопируйте файл `index.html` в память планшета (например, в `Download`).
2. Откройте его в **Chrome for Android** (адрес вида `file:///sdcard/Download/index.html`)
   или через файловый менеджер «Открыть в Chrome».
3. Подключите станок кабелем USB‑OTG.

> Важно: страница должна открываться в **защищённом контексте** (`file://`, `https://` или `localhost`).
> `file://` — подходит.

### Интерфейс

Оформление — тёмная тема в духе **Blender**: серые области `#303030`, виджеты `#545454`,
синее выделение `#4772b3`, оранжевый маркер текущей позиции, компактные «плоские» кнопки.
Вся страница — один экран с траекторией, поверх которого два **сворачиваемых** ящика:

- **слева — «Станок»**: подключение (скорость, «Подключиться», сканирование, окружение/OTG),
  служебные команды GRBL, загрузка G‑кода и **пульт** (джог `X±Y±Z±`, `$H`, обнуление нуля);
- **справа — «Консоль»**: лог обмена со станком и список отправленных строк.

Сверху — **выпадающее меню** (как в Blender): `Файл`, `Вид`, `Станок`, `Прогон`, `Справка`.
Пункты меню не дублируют логику, а нажимают те же кнопки, что и панели; недоступные сейчас
действия (например, «Подключиться» без кабеля) показаны серым, а галочки‑переключатели
(`Быстрые ходы`, `Авто‑прокрутка`, `G21 G90`) помечены точкой справа. Меню закрывается по `Esc`
или щелчку в любом месте; на мыши при открытом меню достаточно навести на соседний заголовок.

Ниже меню — строка статуса (связь, состояние, MPos/WPos, FS, версия GRBL), кнопки
**Пуск / Пауза / Продолжить / Стоп** и полоса прогресса. Легенда траектории — внизу по центру.

Панели **открыты по умолчанию**. Свернуть/развернуть их можно: кнопкой **«✕»** в шапке панели,
кнопкой **«☰»** у кромки экрана (движется вместе с панелью) или пунктами
`Вид → Панель «Станок» / Панель «Консоль»`. Разделы внутри левой панели оформлены
**аккордеоном** (`Подключение`, `Команды GRBL`, `G‑код`, `Пульт управления`) — щёлкните по
заголовку, чтобы раскрыть/свернуть.

### Порядок проверки

1. Раскройте левую панель **«Станок»** → **«Подключение» → «Окружение / OTG»**:
   должно быть `isSecureContext = true` и `'usb' in navigator = true`.
2. Там же выберите скорость `115200` и нажмите **«Подключиться»**
   (или `Станок → Подключиться` в верхнем меню).
   - Если станка нет в списке — включите галочку **«все USB»** и выберите плату вручную.
   - В правой консоли появятся `Endpoints: IN=… OUT=…`, строки `baud 115200 → reg …` и `CH34x инициализирован`.
3. Раздел **«Команды GRBL»** — нажмите **«Статус ?»** или **«Версия $I»**.
   - Норма: в консоли приходит строка вида `<Idle|MPos:0.000,0.000,0.000|FS:0,0>` или `[VER:1.1h.…]`.
   - Если тишина — нажмите **«Soft reset»**, затем ещё раз статус.
   - Если и это не помогло — попробуйте **«Сброс (DTR)»**.
4. Раздел **«G‑код»** — нажмите **«Тест»** (или загрузите свой `.gcode` / вставьте текст и
   нажмите **«Разобрать и показать»**): на экране появится контур, а в правой консоли — список
   команд и прогресс. **Для отрисовки связь не нужна** — визуализатор работает и без станка.
   Жесты: один палец — сдвиг, два пальца / колесо — масштаб; кнопка **«Вписать»**.
5. Раздел **«Пульт управления»** — джог `X±Y±Z±`, кнопка `$H` (homing), обнуление нуля.
6. Кнопки сверху: **«▶ Пуск»** отправит программу на станок потоком (нужно соединение);
   **«⏸» / «⏵» / «⛔»** управляют выполнением.

### Если связи нет — что проверить

- Выберите в списке именно **USB‑устройство CH340** (VID `1A86`).
- Попробуйте скорость `57600`, `250000`, `9600` — некоторые прошивки GRBL настроены иначе.
  (Скорость задаётся **до** подключения.)

### Сообщение «совместимые устройства не найдены» / пустой список

Это вывод пикера Chrome: он не показал ни одного подходящего устройства. Диагностика по шагам:

1. **Нажмите «Диагностика: показать ВСЁ USB»** (пикер без фильтра).
   - Появился список и вы выбрали плату → смотрите её VID:PID в таблице.
     - `1A86` — это WCH (CH340/CH341/CH343/CH9102), драйвер подойдёт.
     - Другой VID (например `10C4` CP2102, `0403` FTDI) → нужен другой драйвер, напишите VID:PID.
   - **Список пуст ВСЕГДА** → Android вообще не видит ни одного USB‑устройства.
     Тогда проблема физическая, а не в коде (см. пункты ниже).
2. **Кабель.** «Быстрая зарядка» — это только про питание. Нужен **кабель данных**
   (линии D+/D−). Проверка: подключите плату ЭТИМ ЖЕ кабелем к ПК — если LaserGRBL
   видит порт, кабель данных; если нет — он зарядный.
3. **OTG‑адаптер.** Кабель USB‑C → USB‑C часто **не** включает режим хоста на планшете.
   Нужен OTG‑адаптер (USB‑C «папа» → USB‑A «мама») + обычный кабель платы USB‑A → USB‑B.
4. **Питание.** Если плата питается от USB, планшет должен отдать ~500 мА. Помогает
   USB‑хаб с внешним питанием (хаб → планшет, плата → хаб).
5. **Порядок.** Подключите плату **до** открытия страницы, затем обновите вкладку.
6. **Планшет.** У части моделей OTG включается отдельным пунктом настроек
   («USB OTG», «Подключать как…»). Независимая проверка — приложение «USB OTG Checker».

Признак, что Android видит плату: системное уведомление «USB‑устройство подключено»
и/или светодиод на плате. Нет уведомления → браузер тут ни при чём.

> ### Тест страницы на ПК через Chrome — не показатель
> Windows уже держит CH340 своим драйвером (`CH341SER_A64` / `oem41.inf`), а WebUSB умеет
> работать с устройством только через **WinUSB**. Поэтому на ноутбуке `claimInterface()`
> вернёт `Access denied` / `SecurityError` — это **не значит**, что код сломан.
> Чтобы проверить страницу на ПК, надо временно подменить драйвер на WinUSB утилитой
> **Zadig** (`Options → List All Devices → USB-SERIAL CH340 → WinUSB`), а потом вернуть
> WCH‑драйвер (в Диспетчере устройств «Удалить устройство» → переподключить кабель →
> Windows поставит `CH341SER` заново). На Android драйвера нет вообще, поэтому WebUSB там
> работает сразу — **планшет и есть целевая платформа**.

## Безопасность и известные особенности Android

- **Сначала нажимайте «Отключить», потом выдёргивайте кабель.** У Chrome for Android есть
  известный глюк: при резком выдёргивании USB‑устройства без корректного закрытия страница
  может «подвесить» браузер, а в редких случаях телефон перезагружается.
- Браузер **не освобождает USB‑устройство при закрытии вкладки** — если что‑то заклинило,
  закройте вкладку и откройте страницу заново, либо переподключите кабель.
- `requestDevice()` работает только после клика пользователя — поэтому подключение по кнопке.
- Табличка с названием платы может не заполниться (`manufacturerName`/`productName` = «—») —
  это нормально для дешёвых CH340, на работу не влияет.

## Что уже реализовано в `index.html` (этапы A–D в одной странице)

Помимо связи (этап A) страница содержит полноценный пульт:

- **Потоковая отправка G‑кода** (этап B) с учётом лимита RX‑буфера GRBL (`charLimit = 120` симв.):
  строки отправляются, пока сумма неподтверждённых символов меньше лимита; на каждый `ok`
  окно расширяется. Обрабатываются `ok`, `error:N` (с номером строки), `ALARM:N`
  (с расшифровкой и авто‑стопом), статусные отчёты `<...>`.
  Кнопки **Пуск / Пауза (`!`) / Продолжить (`~`) / Стоп (`0x18`)**.
- **Парсер G‑кода** (этап C): `G0/G1/G2/G3`, абсолютный/относительный режим (`G90/G91`),
  мм/дюймы (`G20/G21`), `G92`/`G92.1`/`G10`, `M3/M4/M5`. Дуги `G2/G3` аппроксимируются
  отрезками (по `I/J` или радиусу `R`). Комментарии `(…)` и `;…` игнорируются.
- **Визуализация траектории** (Canvas): сетка, быстрые ходы (G0) и рабочие (G1/G2/G3),
  «выполнено» до подтверждённой строки, маркер текущей позиции из отчёта `?`.
  Жесты: один палец — сдвиг, два пальца / колесо — масштаб; кнопка **«Вписать в экран»**.
- **Загрузка файла** `.gcode / .nc / .txt / .gc / .tap / .ngc` или вставка текста в поле,
  кнопка **«Тестовая траектория»** для быстрой проверки отрисовки без файла.
- **Пульт** (этап D): джог `X±Y±Z±` с шагом и подачей (через `$J` для GRBL 1.1 или `G91 G1`),
  кнопка `$H` (homing), обнуление координат `X/Y/Z` (через `G10 L20 P1` — постоянно, либо
  `G92` — временно) и сброс `G92.1`, кнопка «В ноль X0 Y0».
- **Панель «Отправленные команды»** с подсветкой текущей/выполненной/ошибочной строки
  (для файлов > 20 000 строк построчная подсветка отключается — защита от гигантского DOM)
  и авто‑прокруткой.
- **Статус‑бар**: связь, состояние, MPos/WPos, FS, версия GRBL.
  Для GRBL < 1.1 джог через `$J` отключается автоматически (предупреждение в логе).

### Известные упрощения

- Оверрайды подачи (`0x90…0x9D`) и Wake Lock пока не добавлены.
- Перерисовка траектории при отправке троттлится (~6–7 кадров/с), чтобы не грузить слабый
  планшет большим контуром.

## Технические детали драйвера CH340 (для справки)

| Что | Значение |
|---|---|
| VID:PID | `0x1A86:0x7523` (CH340), `0x1A86:0x5523` (CH341A) + клоны |
| Запросы | `0x5F` версия, `0x95` чтение регистра, `0x9A` запись регистра, `0xA1` serial init, `0xA4` modem ctrl |
| Регистры | `0x1312` baud factor, `0x0F2C` baud offset, `0x2518` LCR, `0x2727` flow |
| LCR 8N1 | `0xC3` (RX `0x80` \| TX `0x40` \| CS8 `0x03`) |
| DTR / RTS | `0x20` / `0x40` |
| Baud 115200 | `reg 0x1312 = 0xCC83`, `0x0F2C = 0x08` |

Формула скорости (как в usb-serial-for-android, 12 МГц × 128):

```
factor = 1532620800 / baud; divisor = 3;
while (factor > 0xFFF0 && divisor > 0) { factor >>= 3; divisor--; }
factor = 0x10000 - factor;  divisor |= 0x80;
val1 = (factor & 0xFF00) | divisor;   // → reg 0x1312
val2 = factor & 0xFF;                 // → reg 0x0F2C
```
